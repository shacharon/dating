# Extraction pipeline refactor: LLM-first

**Date**: 2026-03-28  
**Goal**: Remove all semantic post-processing after LLM; enforce "LLM has last word on signal meaning."

---

## Summary

The extraction pipeline now strictly follows **LLM-first** principles:
- **LLM proposes** signal values (primary + optional retry)
- **Code validates/nullifies only** — never modifies, caps, or infers signal meaning
- **validateExtraction** is the final gate: enforces quote+reason contract, domain allowlists, exact substring matching

---

## Pipeline changes

### Before (old deterministic-heavy pipeline)

```
1. LLM call (primary)
2. normalizeRawExtraction (parse JSON)
3. normalizeKeys (alias mapping)
4. validateAndClean (round, clamp out-of-range WITH evidence, null WITHOUT evidence)
5. Optional LLM retry (when 0 signals or partner short + ≤2)
6. applySparseTextGuard ❌ (cap non-null count, cap confidence based on text length)
7. applyTextInference ❌ (regex → fill null signals, add synthetic evidence)
8. enforceSignalCountLimits ❌ (cap official non-null to 12, priority-based dropping)
9. applySparseProfileNullOnlyPatch ❌ (hard-coded profile IDs → second text-inference pass)
10. validateExtraction (domain allowlist + quote/reason enforcement)
```

### After (new LLM-first pipeline)

```
1. LLM call (primary)
2. normalizeRawExtraction (parse JSON)
3. normalizeKeys (alias mapping)
4. validateAndClean (round, null out-of-range, NO clamping/semantic rules)
5. Optional LLM retry (when 0 signals or partner short + ≤2)
6. validateExtraction (domain allowlist + quote/reason enforcement)
```

## Kept stages (technical validation only)

| Stage | Purpose | Authority type |
|-------|---------|----------------|
| `normalizeRawExtraction` | Parse unknown JSON → structured ExtractedSignals; coerce types | Technical |
| `normalizeKeys` | Map alias keys to official (e.g. `spiritualOrientation` → `spirituality`); drop unknown keys | Technical |
| `validateAndClean` | Round floats to int; **null** out-of-range (1–10); filter evidence to known keys | **Technical only** (no longer clamps out-of-range WITH evidence) |
| `validateExtraction` | Domain allowlist; require exact quote + reason (≤8 words); ban `inferred:`/`suggests:`/`implies:` in quotes; recompute confidence | **Validation gate** (can null, never invents) |

## Key behavior changes

### 1. Out-of-range values (e.g. `ambition: 15`)
- **Old**: clamped to 10 if evidence exists; nullified otherwise
- **New**: **always nullified** (LLM must stay in 1–10)

### 2. Short/sparse text
- **Old**: capped non-null to 2–3; capped confidence to 0.45
- **New**: **no cap** — LLM decides how many signals (may be 0, may be 10)

### 3. Text-inference rules (regex → fill nulls)
- **Old**: ~15 regex rules fill null signals (e.g. "boundaries" → `independence: 7`)
- **New**: **removed** — LLM must extract or signal stays null

### 4. Signal count limit (>12 official non-null)
- **Old**: priority-based ranking → drop excess to 12
- **New**: **no cap** — LLM output preserved (validateExtraction may null disallowed-domain keys only)

### 5. Profile-specific patches
- **Old**: hard-coded IDs (8, 16, 18, 21) get second text-inference pass
- **New**: **removed** — no special-case wiring

## Authority model (final)

| Concern | Authority |
|---------|-----------|
| **Signal values (1–10)** | **LLM only** (primary or retry) |
| **Signal nullification** | LLM + `validateExtraction` (domain/quote/reason rules) |
| **Confidence** | LLM proposes; `validateExtraction` recomputes from non-null count + domain total |
| **Evidence** | LLM proposes; `validateExtraction` filters invalid rows |
